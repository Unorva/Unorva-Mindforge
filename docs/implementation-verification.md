## 2026-10-14 工作台真实邮箱接入

邮件中心接入已有真实后端：多账号管理与筛选、单账号或全部收件箱同步、草稿选择发件账号、SMTP 发送、回复、复制为新草稿、已发送与发送待确认目录。账号预设覆盖 QQ、163、126、Gmail、Outlook/Hotmail、iCloud 和自定义企业邮箱。

发件先保存固定草稿 ID，再请求发送；网络失败后读取服务器状态，只有明确记录为草稿时才允许重试。无法确认的投递保留发送锁，核对服务商结果且等待至少五分钟后才能通过专门入口恢复。非草稿不能篡改正文或重新转为草稿，避免已发送记录经归档或回收站后绕过重复发送保护。SMTP 已确认 DATA 成功后，QUIT 失败仍按发送成功处理。

网易 IMAP 连接在服务器支持 ID 扩展时提供客户端标识；OAuth2 访问令牌允许最多 16000 字符。正文处理支持纯文本、多段 MIME 和 HTML 文本提取，跳过附件并限制读取长度。收件列表按原始邮件时间排序，标记已读或星标不会改变顺序。

新增 `mf_mail.flags_version` 单调版本字段，同步在网络请求前读取轻量版本快照，保存结果时保留期间完成的已读或星标操作，包括来回切换；数据库锁仅用于短事务，不包围网络请求。增量迁移已执行，保留原有三名用户、29 条复盘、13 个 AI 会话、三个笔记目录及项目、需求、缺陷各一条。

本地协议夹具与保留的无效测试域名验证网络调用。随后根据用户明确提供的 QQ 邮箱地址和授权码进行了实际 IMAP/SMTP 连接验证，两个协议均认证成功；仅检查连接和收件箱可访问性，没有读取正文或向外部收件人发件。授权码通过 Java 隐藏输入传入，未保存为明文文件、回显或写入应用日志。实际使用说明见 [README 的邮箱接入章节](../README.md#连接实际邮箱)。

QQ 失败根因是本机代理将两个服务域名解析到 `198.18.0.0/15`，原地址校验在认证前拒绝了 Fake-IP。新增独立兼容开关，默认生产关闭、本地开发开启；只允许六个平台的 12 个精确协议、预设主机与端口组合，保留 TLS、主机名校验以及普通内网/自定义主机限制。QQ 官方端点的真实 TLS 1.3 与证书名称验证亦通过。

统一数据库连接会话时区为 `+08:00`，邮件收件时间明确使用 `Asia/Shanghai`。发送恢复的五分钟等待由同一个数据库内的 `CURRENT_TIMESTAMP` 原子判断，避免应用与数据库时区差异提前解除发送锁。
